# 이번 실험을 이해하는 순서

## 무엇을 비교하나요?

한글을 읽고 뜻을 알아내는 문제와, 자모의 위치를 지켜 새로 출력하는 문제는 다릅니다. 이번에는 후자만 평가합니다. 목표는 여러 문체를 만드는 것이 아니라, **음절의 윗줄을 맞춘 한 가지 방식**을 정확하게 생성하는 것입니다.

모델의 선택지는 다음과 같습니다.

| 조건 | 배운 것 | 비교 이유 |
|---|---|---|
| A | 추가학습 없음 | 동일한 기반 모델의 출발점을 확인합니다. |
| B | 한글→자모 배치 + 자모 목록 | 표현 방식과 정답 문자를 학습한 기준선입니다. |
| C | 한글→자모 배치 + 자모·좌표 목록 | B보다 위치를 명시적으로 배우는 것이 도움이 되는지 봅니다. |

따라서 **C 대 B**가 주 비교입니다. ChatGPT 웹에서 관찰한 실패는 연구 동기이며, 다른 기반 모델의 학습 전 성적을 대신하지 않습니다.

## OCR은 어떻게 되었나요?

파일럿(pilot)은 본 실험 전에 작은 규모로 실행 가능성을 살펴보는 과정입니다. 합성 자모 이미지 10개에 EasyOCR을 적용했으나, 원시 출력의 자모 목록이 완전하게 맞은 이미지는 0개였습니다. `오늘`, `구름`은 아예 검출하지 못했습니다.

이 결과를 확인한 뒤 사용자는 **합성 좌표로 보조학습 효과를 먼저 검증**하기로 결정했습니다. 그러므로 이번에 좋아지는 결과가 나오더라도 “OCR이 좋아졌다” 또는 “OCR 학습이 효과적이다”라고 쓰지 않습니다. OCR 실패는 파일럿 결과와 한계로 함께 보고합니다.

## 데이터는 어떻게 나눴나요?

- 학습(train) 198개: 모델의 가중치를 바꾸는 데 사용합니다.
- 검증(validation) 25개: 몇 번째 학습 회차의 모델을 선택할지 결정합니다.
- 테스트(test) 25개: 선택을 끝낸 다음 최종 결과를 측정합니다.

같은 단어가 그대로 들어 있는 문구는 같은 그룹으로 묶었습니다. 그래도 한국어 음절이나 일부 형태소는 여러 분할에 공통으로 나타납니다. 이 실험은 한 번도 본 적 없는 자모를 알아내는 문제가 아니라, **아는 자모로 새로운 단어·문구의 배치를 구성하는 문제**입니다.

## 학습 코드는 어디를 보면 되나요?

1. `jamo/core.py`: 정답 자모와 좌표를 어떻게 만드는지 봅니다. 이 코드는 정답 자료와 채점에 사용하며, 데모에서 모델 대신 실행하지 않습니다.
2. `jamo/prompts.py`: 모델에 주는 동일한 변환 지시입니다. 실험 입력 지시는 고정된 영어 문장입니다. 코드 설명·주석과 논문 언어는 별도로 관리합니다.
3. `training/train.py`: LoRA 설정, 입력 부분의 손실 제외, 두 과제의 손실 합산, 기울기 누적을 봅니다.
4. `evaluation/predict.py`: 생성한 출력의 공백을 그대로 저장하는지 확인합니다.
5. `training/reproduce.py`: 검증 결과로 선택을 고정한 뒤 테스트를 여는 순서를 확인합니다.

LoRA는 기반 모델의 큰 가중치를 고정하고 작은 추가 행렬을 학습하는 방법입니다. 체크포인트(checkpoint)는 특정 시점의 학습된 가중치를 저장한 것입니다. 에포크(epoch)는 전체 학습 자료를 한 번 본 회차입니다.

주 과제와 보조 과제의 손실(loss)은 각각 출력 토큰 평균으로 계산한 뒤 0.5씩 합칩니다. C의 보조 출력은 좌표 때문에 길어집니다. 같은 학습 횟수라도 처리 토큰 수와 실행 시간은 달라질 수 있으므로 함께 보고합니다.

## 어떤 결과가 정답인가요?

자모를 모두 포함해도 받침이 옆 음절 아래에 있으면 생성 실패입니다. 주 지표는 **엄격 격자 일치율**입니다. 줄 끝 공백, 바깥 빈 줄, 운영체제별 줄바꿈 표현 차이만 무시합니다. 자모 누락·중복과 문자 목록 보존율도 따로 기록합니다.

모델 선택은 검증 자료의 격자 정답 수 → 자모 목록 정답 수 → 더 이른 학습 회차 순입니다. 배포 후보의 B/C 성적이 완전히 같으면 B를 선택합니다. 테스트 성적을 보고 이 기준을 바꾸지 않습니다.

## 결과를 해석할 때 주의할 점

학습 손실이 낮아졌다는 사실만으로 배치 생성이 성공했다고 결론내리지 않습니다. 실제 새 문구에 무엇을 출력했는지 확인합니다. 두 모델이 모두 실패하거나 C가 더 낮아도 유효한 관찰이며, 실제 결과를 그대로 적습니다.

한 번의 난수 시드(seed), 작은 데이터, 한 가지 스타일이라는 한계가 있습니다. 이 결과만으로 모든 한국어 생성이나 모든 언어모델에서 성능이 좋아진다고 주장할 수 없습니다. 정답 생성 규칙만으로도 이 스타일을 구현할 수 있다는 점도 명시합니다.
